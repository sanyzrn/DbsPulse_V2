# DbsPulse

سامانه ارزیابی عملکرد سازمانی — مدیریت فرآیند ارزیابی عملکرد پرسنل پیش از تمدید قرارداد، با زنجیره تأیید چهارمرحله‌ای (مسئول واحد → منابع انسانی → معاونت → مدیرعامل) و خروجی نهایی قابل چاپ/PDF.

مشخصات کامل کسب‌وکار در فایل [`پرامپت_ساخت_کلود_کد.md`](./پرامپت_ساخت_کلود_کد.md) مستند شده است.

## پشته فنی

- **Backend:** FastAPI (Python) + SQLAlchemy 2.0 + Alembic + PostgreSQL 16
- **Frontend:** React + TypeScript + Vite + Tailwind CSS (کاملاً RTL، فونت Vazirmatn)
- **Auth:** JWT (access + refresh)، هش رمز با Argon2
- **نمودار:** Recharts (رادار شایستگی، روند فرد)
- **خروجی PDF:** WeasyPrint + Jinja2

## پیش‌نیازها

- Python 3.11+
- Node.js 20+
- PostgreSQL 16 (یا Docker برای اجرای آن)

## راه‌اندازی دیتابیس

اگر Docker در دسترس دارید، ساده‌ترین راه استفاده از `docker-compose.yml` موجود در ریشه پروژه است:

```bash
docker compose up -d db
```

این کار یک PostgreSQL روی پورت ۵۴۳۲ با کاربر/رمز/دیتابیس `dbspulse` بالا می‌آورد (مطابق `backend/.env.example`).

اگر Docker ندارید، هر PostgreSQL 16 محلی دیگری هم کافی است؛ فقط کاربر و دیتابیسی با همان مشخصات (یا مقادیر دلخواه خودتان) بسازید و `DATABASE_URL` را در `.env` به همان مقدار تنظیم کنید.

## راه‌اندازی Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate        # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # در صورت نیاز مقادیر را ویرایش کنید

alembic upgrade head             # اجرای تمام migration ها + seed data

uvicorn app.main:app --reload --port 8000
```

بک‌اند روی `http://localhost:8000` بالا می‌آید. مستندات تعاملی API در `http://localhost:8000/docs` قابل مشاهده است.

### چه چیزی توسط migration ها ساخته می‌شود؟

- تمام جداول بخش ۵ سند مشخصات (`personnel`, `users`, `evaluation_access`, `indicators`, `evaluation_records`, `evaluation_scores`, `evaluation_comments`, `audit_log`)
- شاخص‌های عمومی (۱۲ مورد، وزن ۶۰٪) و تخصصی (۸ مورد، وزن ۴۰٪) به‌صورت seed، دقیقاً مطابق بخش ۷ سند
- شماره‌گذار خودکار کد ارزیابی (`EVL-0001`, `EVL-0002`, …)
- چند کاربر و پرسنل نمونه برای تست کامل هر ۴ نقش (جدول زیر)

## راه‌اندازی Frontend

```bash
cd frontend
npm install
npm run dev
```

فرانت‌اند روی `http://localhost:5173` بالا می‌آید و درخواست‌های `/api/*` به‌صورت خودکار به بک‌اند (پورت ۸۰۰۰) پروکسی می‌شوند.

## کاربران نمونه (seed) برای تست

پس از اجرای `alembic upgrade head`، این حساب‌ها برای تست هر چهار نقش آماده‌اند (رمز عبور همه: `DbsPulse@12345` — **فقط برای محیط توسعه؛ پیش از استقرار واقعی حتماً تغییر دهید**):

| نام کاربری | نقش | توضیح |
|---|---|---|
| `hr1` | منابع انسانی | مدیریت پرسنل/کاربران/شاخص‌ها، صف بررسی، داشبورد تحلیلی |
| `sup1` | مسئول واحد | ارزیاب «علی محمدی» (P-1001، واحد فروش) |
| `sup2` | مسئول واحد | ارزیاب «زهرا کریمی» (P-1002، واحد فناوری اطلاعات) |
| `dep1` | معاونت | معاونت هر سه پرسنل نمونه؛ برای «حسین رضایی» (P-1003) نمره‌دهنده اول هم هست چون عنوان شغلی او «مدیر» است |
| `ceo1` | مدیرعامل | تأییدکننده نهایی هر سه پرسنل نمونه |

برای دیدن گردش‌کار کامل یک ارزیابی واقعی: با `sup1` وارد شوید → «علی محمدی» را ارزیابی کنید → با `hr1` تأیید کنید → با `dep1` تأیید کنید → با `ceo1` تأیید نهایی بزنید و خروجی PDF را ببینید. برای مسیر ویژه «مدیر»: با `dep1` وارد شوید و ارزیابی «حسین رضایی» را مستقیماً شروع کنید.

## اجرای کامل با Docker (استقرار)

برای اجرای کل استک (دیتابیس + بک‌اند + فرانت‌اند) با یک دستور:

```bash
docker compose up -d --build
```

- بک‌اند روی `http://localhost:8000` (با migration های خودکار در استارت‌آپ، طبق `backend/docker-entrypoint.sh`)
- فرانت‌اند (Nginx + build استاتیک) روی `http://localhost:8080`، که درخواست‌های `/api/*` را داخلی به بک‌اند پروکسی می‌کند
- پورت‌های دیتابیس (۵۴۳۲) و بک‌اند (۸۰۰۰) فقط روی loopback (`127.0.0.1`) منتشر می‌شوند؛ تنها نقطه ورود از شبکه، فرانت‌اند (پورت ۸۰۸۰) است

پیش از استقرار واقعی (نه صرفاً تست محلی) حتماً:
1. مقدار `JWT_SECRET_KEY` را در `docker-compose.yml` (یا بهتر، از طریق فایل `.env` جدا) به یک مقدار تصادفی و طولانی تغییر دهید — با `ENVIRONMENT=production` برنامه عمداً از استارت‌شدن با مقدار پیش‌فرض دمو جلوگیری می‌کند.
2. رمزهای کاربران seed (`DbsPulse@12345`) را عوض یا کاربرهای دمو را حذف کنید.
3. یک لایه HTTPS جلوی سرویس `frontend` (پورت ۸۰۸۰) قرار دهید — نمونه پیکربندی Nginx + Certbot در [`deploy/nginx-https.conf.example`](./deploy/nginx-https.conf.example) موجود است.

## اجرای تست‌های خودکار

تست‌های بک‌اند (pytest) منطق حساس پروژه را پوشش می‌دهند: قانون شواهد ۱۵ کلمه‌ای، محاسبه امتیاز و آستانه‌ها، ماشین حالت گردش‌کار (مسیر عادی و مسیر ویژه «مدیر»)، و کنترل دسترسی هر نقش. هر تست در یک تراکنش/savepoint جدا اجرا و در پایان rollback می‌شود، پس نیازی به پاک‌سازی دستی نیست.

```bash
cd backend
source .venv/bin/activate
pip install -r requirements-dev.txt

# یک دیتابیس تست جدا بسازید (فقط یک‌بار لازم است)
psql -h localhost -U dbspulse -c "CREATE DATABASE dbspulse_test OWNER dbspulse;"

pytest -v
```

این تست‌ها به‌صورت خودکار روی هر push/PR هم با GitHub Actions اجرا می‌شوند (`.github/workflows/ci.yml`)، همراه با build فرانت‌اند.

## نکات امنیتی

- تمام endpoint های تغییردهنده داده پشت بررسی نقش (`role`) در بک‌اند قفل‌اند، نه فقط مخفی‌کردن دکمه در UI.
- دسترسی به یک رکورد ارزیابی یا پرسنل خاص علاوه بر نقش پایه، از روی `evaluation_access` (یا فیلدهای کپی‌شده روی خود رکورد ارزیابی) هم بررسی می‌شود.
- رمز عبور با Argon2 هش می‌شود.
- ورود (`/api/auth/login`) در برابر brute-force محدود شده (۱۰ تلاش در دقیقه به ازای هر IP). پشت reverse proxy، IP واقعی از `X-Forwarded-For` خوانده می‌شود؛ در استقرار واقعی متغیر `FORWARDED_ALLOW_IPS` را به IP/شبکه پروکسی محدود کنید.
- در حالت `ENVIRONMENT=production` مستندات Swagger (`/docs` و `/openapi.json`) عمداً غیرفعال می‌شوند.
- تغییر رمز یک کاربر توسط HR بلافاصله تمام نشست‌های (access/refresh token) قبلی همان کاربر را باطل می‌کند.
- برای استقرار واقعی: پشت HTTPS/reverse proxy قرار دهید (نمونه در `deploy/nginx-https.conf.example`)، `JWT_SECRET_KEY` را به یک مقدار تصادفی و طولانی تغییر دهید (`ENVIRONMENT=production` این را اجباری می‌کند) و رمزهای seed را عوض یا حذف کنید.
- `CORS_ORIGINS` را به دامنه واقعی frontend محدود کنید (پیش‌فرض فقط برای لوکال/دمو باز است).
