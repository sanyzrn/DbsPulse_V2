# استقرار روی سیستم سازمان — بدون تحویل کد منبع

این راهنما برای همان حالتی نوشته شده که سامانه روی سرور *سازمان* اجرا می‌شود،
ولی کدِ منبع تحویل داده نمی‌شود.

---

## اول: چه چیزی واقعاً محافظت می‌شود و چه چیزی نه

صادقانه: **روی ماشینی که در اختیار طرف مقابل است، محافظتِ مطلق ممکن نیست.**
هر چیزی که برای اجرا شدن روی آن ماشین باشد، در نهایت قابل استخراج است. کاری که
می‌شود کرد این است که فاصلهٔ بین «کد جلوی چشمشان است» و «باید عمداً برای بیرون
کشیدنش تلاش کنند» تا حد ممکن زیاد شود.

| روش | چه چیزی می‌دهد |
|---|---|
| **میزبانی نزد خودتان** (سرور شما، آن‌ها فقط یک نشانی می‌گیرند) | تنها محافظتِ کامل. کد هرگز از ماشین شما بیرون نمی‌رود |
| **تحویل ایمیج داکر** (همین راهنما) | نه فایل `.py` روی دیسکشان هست، نه مخزن git، نه تاریخچه. استخراجش ممکن است ولی کارِ عمدی و آگاهانه می‌خواهد |
| **تحویل پوشهٔ سورس** | هیچ. کل کد، کل تاریخچهٔ git، همه‌چیز |

اگر میزبانی نزد خودتان ممکن است، همان بهترین است. اگر نه، مسیر داکر را بروید —
که تفاوتِ عملی‌اش با تحویل سورس زیاد است:

* **فرانت‌اند** اصلاً سورس ندارد. ایمیج فقط جاوااسکریپتِ ساخته و فشرده‌شده دارد؛
  کدِ React جایی در آن نیست.
* **بک‌اند** فایل‌های پایتون را دارد، ولی داخل ایمیج داکر — نه روی دیسکِ سرور.
  برای رسیدن به آن باید بدانند ایمیج چیست و عمداً بازش کنند.
* **مخزن git**، تاریخچهٔ کامیت‌ها، تست‌ها، مستندات داخلی و فایل‌های ممیزی هیچ‌کدام
  منتقل نمی‌شوند.

و مهم‌تر از هر راه‌حل فنی: **قرارداد**. یک بند صریح «حق استفاده داده می‌شود، نه
مالکیت؛ بازمهندسی معکوس و کپی ممنوع است» کاری می‌کند که هیچ ابزار فنی نمی‌کند.

## مرحلهٔ ۱ — ساخت ایمیج‌ها (روی سیستم خودتان)

```bash
docker compose build
docker save dbspulse-backend dbspulse-frontend -o dbspulse-images.tar
```

فایل `dbspulse-images.tar` ساخته می‌شود. حجمش حدود یک گیگابایت است.

## مرحلهٔ ۲ — آماده‌کردن تنظیمات

```bash
cp .env.production.example .env
```

`.env` را باز کنید و پرش کنید. سه مقدار حتماً باید تصادفی ساخته شوند:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"   # POSTGRES_PASSWORD
python -c "import secrets; print(secrets.token_urlsafe(64))"   # JWT_SECRET_KEY
python -c "import secrets; print(secrets.token_urlsafe(18))"   # DBSPULSE_ADMIN_PASSWORD
```

> اگر هرکدام از این‌ها روی مقدار توسعه‌ای بماند، بک‌اند عمداً بالا **نمی‌آید** و
> دلیلش را در لاگ می‌نویسد. این عمدی است: راه‌اندازیِ ناامن نباید بی‌سروصدا موفق شود.

`CORS_ORIGINS` و `PUBLIC_BASE_URL` را روی نشانی واقعیِ سامانه بگذارید.
`PUBLIC_BASE_URL` داخل QR سندهای PDF می‌رود، پس باید از بیرونِ سازمان هم باز شود.

## مرحلهٔ ۳ — انتقال به سرور سازمان

فقط این سه فایل منتقل می‌شوند:

```
dbspulse-images.tar
docker-compose.prod.yml
.env
```

**پوشهٔ `backend/`، پوشهٔ `frontend/`، و `.git` منتقل نمی‌شوند.**

## مرحلهٔ ۴ — اجرا

```bash
docker load -i dbspulse-images.tar
docker compose -f docker-compose.prod.yml up -d
```

سامانه روی پورت ۸۰۸۰ بالا می‌آید (با `HTTP_PORT` در `.env` قابل تغییر است).
مایگریشن‌ها خودشان اجرا می‌شوند و بک‌اند بعد از پایانِ موفقشان بالا می‌آید.

نخستین حساب مدیر با همان `DBSPULSE_ADMIN_USERNAME` و `DBSPULSE_ADMIN_PASSWORD`
ساخته می‌شود و در اولین ورود، تغییر رمز اجباری است. اگر رمز را در `.env`
نگذاشته باشید، یک رمز تصادفی ساخته و **فقط یک‌بار** در لاگ نوشته می‌شود:

```bash
docker compose -f docker-compose.prod.yml logs backend | grep -i admin
```

## مرحلهٔ ۵ — بررسی سلامت

```bash
docker compose -f docker-compose.prod.yml ps          # هر سه سرویس بالا
curl -s http://localhost:8080/api/health/ready        # باید ok بدهد
```

## HTTPS

بدون HTTPS، کوکی رفرش پرچم `Secure` می‌گیرد و ورود اصلاً کار نمی‌کند — یعنی
HTTPS اختیاری نیست. نمونهٔ پیکربندی nginx در همین پوشه است:
`deploy/nginx-https.conf.example`.

`FORWARDED_ALLOW_IPS` را روی IP همان پروکسی بگذارید. با `*` هر کلاینتی می‌تواند
هدر `X-Forwarded-For` جعلی بفرستد و محدودیت نرخِ ورود را دور بزند؛ به همین دلیل
`*` در حالت production باعث خطای صریح استارت‌آپ می‌شود.

## بک‌آپ

دیتابیس در volume با نام `dbspulse_pgdata` است و هیچ پورتی از آن منتشر نمی‌شود.

```bash
docker compose -f docker-compose.prod.yml exec -T db \
  pg_dump -U dbspulse dbspulse > backup-$(date +%F).sql
```

## به‌روزرسانی نسخه

روی سیستم خودتان دوباره `build` و `save` کنید، فایل tar تازه را ببرید، و:

```bash
docker load -i dbspulse-images.tar
docker compose -f docker-compose.prod.yml up -d
```

داده‌ها در volume می‌مانند و مایگریشن‌های تازه خودشان اجرا می‌شوند.

## آنچه نباید روی سرور سازمان اجرا شود

`setup_and_run.bat` **فقط برای توسعهٔ محلی است**. آن اسکریپت عمداً
`ENVIRONMENT=development` و یک `JWT_SECRET_KEY` ثابت می‌نویسد، کاربران نمونه با
رمز مشترک می‌سازد، و `MIN_COHORT_SIZE=1` می‌گذارد که سرکوبِ آمارِ گروه‌های کوچک
را خاموش می‌کند. هیچ‌کدام روی یک استقرار واقعی درست نیست.
